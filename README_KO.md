MARORONG CARD WAR - Phase 22 3D Prototype 01

기준: 사용자가 제공한 Phase 21 UI Fixed HTML을 유지한 Three.js 선택형 그래픽 시제품.

원본: legacy/Phase21_Original.html
실행 HTML: Marorong_Card_War_Phase22_3D_Prototype.html
그래픽 코드: src/scene.js, src/boot.js, src/depth.css
빌드 명령: python build.py
3D 라이브러리 로컬 준비: npm install && npm run vendor
검증 명령: python tests/static_audit.py 및 Python Playwright Chromium 검사

게임 데이터와 규칙을 3D 엔진에서 다시 계산하지 않습니다. 3D 레이어는 기존 DOM 및 공개 상태를 읽어서 표현합니다.

미검증 사항: 실물 WebGL Three.js 구동 여부, 모바일 실기기, 개별 카드 일러스트, 모든 능력 간 상호작용. CI 결과를 확인한 후에만 통과로 보고합니다.

이 프로젝트는 별도 빌드를 위한 소스 구조를 제공하며 완성된 3D 게임을 의미하지 않습니다.

Phase 23 - 3D 전장 카드 호버·선택 강조
- 마우스가 가리키는 전장 카드만 상승하고 카드 주변에 입체 광륜을 표시합니다.
- 선택한 카드와 공격 대상은 별도 강조됩니다.
- 다른 카드의 위치와 게임 판정은 변경하지 않습니다.
- 원본 2D 호버, 대상 선택, 저장, AI는 Phase21 코드가 담당합니다.
- 빌드: python build.py
- 실행본: Marorong_Card_War_Phase23_3D_Prototype.html
- 실제 WebGL 호버와 게임 상태 불변 여부는 GitHub Actions의 tests/webgl_e2e.py를 통과해야 완료로 보고합니다.

Phase 24 - Three.js 카드 문양과 프레임 개편
- 기존 게임 데이터·능력을 변경하지 않고 유형별 장식 문양과 금속 프레임을 생성합니다.
- 전장 카드 앞면 CanvasTexture, 선택 강조와 금속색이 실제 카드 종류에 맞게 갱신됩니다.
- 카드 이름·체력 및 실제 명령은 기존 HTML에서 계속 표시합니다.
- 실제 Chromium WebGL 카드 텍스처 수 검증을 통과한 뒤 완료 처리합니다.

Phase 25 - Three.js 전장 분위기/조명
- 실제 #arena 화면 크기를 추적하는 4면 금속 림과 청록·호박 조명 영역을 표시합니다.
- 그래픽은 HTML UI를 가리거나 게임 입력을 빼앗지 않도록 투명·비상호작용으로 유지합니다.
- 전장 크기 변경을 렌더 프레임에 반영하며 슬롯 주소와 자원·AI 로직은 유지합니다.
- WebGL 실제 장면 생성 수와 포인터 이벤트 투과 검사를 자동화합니다.

Phase 26 - 공격·회복·소환 전투 연출과 화면 격리
- 기존 DOM의 fx-hit, fx-heal, fx-summon 신호를 시각 효과로만 사용합니다.
- 링, 파편, 상승 입자 애니메이션은 확정 전투 계산과 독립적으로 실행하고 종료 시 자원을 해제합니다.
- WebGL 그리기는 #arena 실제 화면 좌표로 클리핑하여 UI·손패를 가리지 않습니다.
- 3종의 시각 효과 발동/반환, 자원 해제, 게임 스냅샷 불변을 Chromium으로 검증합니다.

Phase 27 - 전장 카드 공개 체력의 3D 시각 정합성
- 전장에 실제 공개된 HP바만 Three.js 위에 얇게 미러링하고 현재 HP 비율과 색상을 일치시킵니다.
- HP 계산, 카드 데이터, AI, 저장 규칙은 원본 그대로이며 게임 상태에 쓰지 않습니다.
- 3D 객체 소멸 시 체력바 메쉬를 폐기하며, 없는 카드/HP 없는 카드는 그리지 않습니다.
- Phase 27의 실제 Chromium WebGL 검증에서 기존 HP 표시와 3D 미러 비율의 동일성을 검사합니다.

Phase 28 - 손패/적 손패 장식 강화
- 손패 카드의 내부 금속 테두리, 카드 선택 조명 및 그림자를 강화합니다.
- 적 손패의 카드 뒷면을 입체적인 문양·프레임으로 표현합니다.
- 손패 부채꼴의 실제 크기, 위치, z-index, 호버·드래그, 카드 장수 및 게임 상태는 기존 Phase21 엔진이 담당하며 수정하지 않습니다.
- 1920x1080 및 모바일 390x844 Chromium에서 실제 포인터 호버 이후 다른 손패가 사라지지 않는지 검사합니다.

Phase 29 - 카드 유형별 절차적 일러스트 개선
- 기존 공개 카드 이름과 종류만으로 성채·함선·마법·수정·전사의 실루엣 및 배경을 Canvas에 그립니다.
- 카드별 이름으로 결정되는 고정 시드로 매번 동일한 구도가 유지됩니다.
- 외부 에셋을 구매하거나 저작권 불명인 이미지를 수집하지 않았습니다. 244장 개별 고급 일러스트가 완성됐다는 의미는 아닙니다.
- 기존 게임 코드와 텍스트·능력치 표현은 보존됩니다.

Phase 30 - 전장 코너의 3D 장식과 반응형 조명
- 기존 전장 경계와 카드 배치를 변경하지 않고 화면 안쪽 4개 코너에 작은 금속 룬 장식을 추가합니다.
- 청록 및 호박색 조명을 느리게 움직이도록 개선하며 모션 감소 설정 시 움직임을 중지합니다.
- 작은 화면에서는 코너 장식을 자동으로 감추고 전장 위에서만 렌더링합니다.
- 새로운 카드 능력이나 전투 판정은 추가하지 않았으며 Three.js 시각 연출에만 적용합니다.

Phase 31 - 카드별 고정 문장·문양 변형
- 공개된 카드 이름과 종류의 고정 해시로 8가지 휘장, 4가지 조명 위치와 5가지 문양을 조합합니다.
- 같은 카드의 그림은 재실행해도 유지되며 다른 카드에서는 화풍 내 변주를 제공합니다.
- 기존 일러스트 영역, 카드 수치, 비용, UI 입력, 규칙과 게임 데이터는 변경하지 않습니다.
- 고유 일러스트 244장 제작 완료가 아니라 카드별 절차적 차별화 단계입니다.

Phase 32 - 전장 행 간격 기반 바닥 인레이
- 실제 전장 행의 DOM 위치를 이용해 카드 영역이 아닌 행 사이에 얇은 금속 가이드 및 작은 문양을 그립니다.
- Three.js 평면 및 입력을 가로채지 않는 HTML 시각층을 동일 위치에 배치합니다.
- 화면 크기 변화에 따라 자동 재배치되며 3D 모드를 끄면 전부 제거합니다.
- 카드 명령·체력·AI와 저장 데이터는 변경하지 않습니다.

Phase 33 - 공격 대상 화살표
- 기존 게임에서 선택된 전장 카드와 공격 대상으로 이미 표시된 슬롯 위로 마우스를 올렸을 때만 화살표를 보여줍니다.
- SVG 오버레이와 Three.js 곡선 메쉬는 표시만 하고 포인터 이벤트와 게임 상태를 건드리지 않습니다.
- 마우스가 벗어나거나 3D 모드를 종료하면 화살표를 제거하고 GPU 자원도 해제합니다.
- 테스트는 클래스 입력으로 시각 상태만 자극하며 새로운 공격 규칙이나 자동 타격을 만들지 않습니다.

Phase 34 - 공격 화살표의 대상 초점 표시
- 기존 Phase 33 합법 공격대상 위에만 원형 조준점과 축소/확대 반응을 더합니다.
- 모션 감소 설정에서는 정적인 표식으로 유지하고 클릭 및 전투 판정은 건드리지 않습니다.
- SVG 생성과 제거, 입력 투과를 Chromium과 WebGL에서 검증합니다.

Phase 35 - 실제 공개 체력 변화량 시각화
- 원본 전장 HP바의 이전/현재 표시 비율 차이가 생겼을 때만 카드 주변에 체력 ±N%p를 표시합니다.
- 이 수치는 화면상 HP 비율의 퍼센트포인트 변화이며 실제 공격력이나 치유량의 게임 내부 계산 결과를 뜻하지 않습니다.
- 피해는 주황, 회복은 청록. 1초 후 표시 제거, 최대 12개, 포인터 이벤트 없음, 3D 종료 시 전량 제거.
- 테스트는 공개 DOM HP바만 일시 변경하고 원상 복구해 실제 게임 상태가 바뀌지 않음을 검사합니다.

Phase 36 - 화면 크기별 Three.js 그래픽 품질과 복귀 안정성
- 작은 뷰포트에서는 3D만 약 20FPS, 큰 화면에서는 기존 약 30FPS 목표를 사용하며 게임 엔진의 시간·턴·AI는 그대로 유지합니다.
- WebGL 해상도 비율은 PC에서 최대 1.5, 좁은 화면에서는 1.25, 시스템 모션 감소 시 1.0으로 제한합니다.
- 실제 Chromium 창 크기를 FHD에서 1366x768 및 390x844로 변경했다가 복귀시키며 슬롯과 전장 클리핑, 입력 투과, 게임 스냅샷 보존을 검사합니다.
- 이 변경은 그래픽 부하 조절이지 실제 물리 기기에서의 FPS 성능 수치 측정은 아닙니다.

Phase 37 - 별도로 열 수 있는 실제 원근 3D 카드 쇼케이스
- 카드게임 화면의 3D 카드 감상 버튼으로 PerspectiveCamera를 사용한 실시간 WebGL 뷰어를 엽니다.
- 두께 있는 금속 프레임과 반사 재질, 부유 애니메이션 및 별도 조명을 표현합니다.
- 쇼케이스는 명시적으로 닫을 수 있고 원본 게임 엔진과 턴을 변경하지 않습니다.
- 현재 뷰어는 데모 카드 표현입니다. Phase 39에서 실제 필드 카드 데이터를 연결할 예정입니다.
