MARORONG CARD WAR - Phase 22 3D Prototype 01

기준: 사용자가 제공한 Phase 21 UI Fixed HTML을 유지한 Three.js 선택형 그래픽 시제품.

원본: legacy/Phase21_Original.html
실행 HTML: Marorong_Card_War_Phase22_3D_Prototype.html
그래픽 코드: src/scene.js, src/boot.js, src/depth.css
빌드 명령: python build.py
3D 라이브러리 로컬 준비: npm install && npm run vendor
검증 명령: python tests/static_audit.py 및 Python Playwright Chromium 검사

게임 데이터와 규칙을 3D 엔진에서 다시 계산하지 않습니다. 3D 레이어는 기존 DOM 및 공개 상태를 읽어서 표현합니다.

미검증 사항: 실물 WebGL Three.js 구동 여부, 모바일 실기기, 개별 카드 일러스트, 모든 능력 간 상호작용. CI 결과를 확인한 후에만 통과로 보고합니다.

이 프로젝트는 별도 빌드를 위한 소스 구조를 제공하며 완성된 3D 게임을 의미하지 않습니다.

Phase 23 - 3D 전장 카드 호버·선택 강조
- 마우스가 가리키는 전장 카드만 상승하고 카드 주변에 입체 광륜을 표시합니다.
- 선택한 카드와 공격 대상은 별도 강조됩니다.
- 다른 카드의 위치와 게임 판정은 변경하지 않습니다.
- 원본 2D 호버, 대상 선택, 저장, AI는 Phase21 코드가 담당합니다.
- 빌드: python build.py
- 실행본: Marorong_Card_War_Phase23_3D_Prototype.html
- 실제 WebGL 호버와 게임 상태 불변 여부는 GitHub Actions의 tests/webgl_e2e.py를 통과해야 완료로 보고합니다.

Phase 24 - Three.js 카드 문양과 프레임 개편
- 기존 게임 데이터·능력을 변경하지 않고 유형별 장식 문양과 금속 프레임을 생성합니다.
- 전장 카드 앞면 CanvasTexture, 선택 강조와 금속색이 실제 카드 종류에 맞게 갱신됩니다.
- 카드 이름·체력 및 실제 명령은 기존 HTML에서 계속 표시합니다.
- 실제 Chromium WebGL 카드 텍스처 수 검증을 통과한 뒤 완료 처리합니다.

Phase 25 - Three.js 전장 분위기/조명
- 실제 #arena 화면 크기를 추적하는 4면 금속 림과 청록·호박 조명 영역을 표시합니다.
- 그래픽은 HTML UI를 가리거나 게임 입력을 빼앗지 않도록 투명·비상호작용으로 유지합니다.
- 전장 크기 변경을 렌더 프레임에 반영하며 슬롯 주소와 자원·AI 로직은 유지합니다.
- WebGL 실제 장면 생성 수와 포인터 이벤트 투과 검사를 자동화합니다.

Phase 26 - 공격·회복·소환 전투 연출과 화면 격리
- 기존 DOM의 fx-hit, fx-heal, fx-summon 신호를 시각 효과로만 사용합니다.
- 링, 파편, 상승 입자 애니메이션은 확정 전투 계산과 독립적으로 실행하고 종료 시 자원을 해제합니다.
- WebGL 그리기는 #arena 실제 화면 좌표로 클리핑하여 UI·손패를 가리지 않습니다.
- 3종의 시각 효과 발동/반환, 자원 해제, 게임 스냅샷 불변을 Chromium으로 검증합니다.

Phase 27 - 전장 카드 공개 체력의 3D 시각 정합성
- 전장에 실제 공개된 HP바만 Three.js 위에 얇게 미러링하고 현재 HP 비율과 색상을 일치시킵니다.
- HP 계산, 카드 데이터, AI, 저장 규칙은 원본 그대로이며 게임 상태에 쓰지 않습니다.
- 3D 객체 소멸 시 체력바 메쉬를 폐기하며, 없는 카드/HP 없는 카드는 그리지 않습니다.
- Phase 27의 실제 Chromium WebGL 검증에서 기존 HP 표시와 3D 미러 비율의 동일성을 검사합니다.

Phase 28 - 손패/적 손패 장식 강화
- 손패 카드의 내부 금속 테두리, 카드 선택 조명 및 그림자를 강화합니다.
- 적 손패의 카드 뒷면을 입체적인 문양·프레임으로 표현합니다.
- 손패 부채꼴의 실제 크기, 위치, z-index, 호버·드래그, 카드 장수 및 게임 상태는 기존 Phase21 엔진이 담당하며 수정하지 않습니다.
- 1920x1080 및 모바일 390x844 Chromium에서 실제 포인터 호버 이후 다른 손패가 사라지지 않는지 검사합니다.

Phase 29 - 카드 유형별 절차적 일러스트 개선
- 기존 공개 카드 이름과 종류만으로 성채·함선·마법·수정·전사의 실루엣 및 배경을 Canvas에 그립니다.
- 카드별 이름으로 결정되는 고정 시드로 매번 동일한 구도가 유지됩니다.
- 외부 에셋을 구매하거나 저작권 불명인 이미지를 수집하지 않았습니다. 244장 개별 고급 일러스트가 완성됐다는 의미는 아닙니다.
- 기존 게임 코드와 텍스트·능력치 표현은 보존됩니다.

Phase 30 - 전장 코너의 3D 장식과 반응형 조명
- 기존 전장 경계와 카드 배치를 변경하지 않고 화면 안쪽 4개 코너에 작은 금속 룬 장식을 추가합니다.
- 청록 및 호박색 조명을 느리게 움직이도록 개선하며 모션 감소 설정 시 움직임을 중지합니다.
- 작은 화면에서는 코너 장식을 자동으로 감추고 전장 위에서만 렌더링합니다.
- 새로운 카드 능력이나 전투 판정은 추가하지 않았으며 Three.js 시각 연출에만 적용합니다.

Phase 31 - 카드별 고정 문장·문양 변형
- 공개된 카드 이름과 종류의 고정 해시로 8가지 휘장, 4가지 조명 위치와 5가지 문양을 조합합니다.
- 같은 카드의 그림은 재실행해도 유지되며 다른 카드에서는 화풍 내 변주를 제공합니다.
- 기존 일러스트 영역, 카드 수치, 비용, UI 입력, 규칙과 게임 데이터는 변경하지 않습니다.
- 고유 일러스트 244장 제작 완료가 아니라 카드별 절차적 차별화 단계입니다.

Phase 32 - 전장 행 간격 기반 바닥 인레이
- 실제 전장 행의 DOM 위치를 이용해 카드 영역이 아닌 행 사이에 얇은 금속 가이드 및 작은 문양을 그립니다.
- Three.js 평면 및 입력을 가로채지 않는 HTML 시각층을 동일 위치에 배치합니다.
- 화면 크기 변화에 따라 자동 재배치되며 3D 모드를 끄면 전부 제거합니다.
- 카드 명령·체력·AI와 저장 데이터는 변경하지 않습니다.

Phase 33 - 공격 대상 화살표
- 기존 게임에서 선택된 전장 카드와 공격 대상으로 이미 표시된 슬롯 위로 마우스를 올렸을 때만 화살표를 보여줍니다.
- SVG 오버레이와 Three.js 곡선 메쉬는 표시만 하고 포인터 이벤트와 게임 상태를 건드리지 않습니다.
- 마우스가 벗어나거나 3D 모드를 종료하면 화살표를 제거하고 GPU 자원도 해제합니다.
- 테스트는 클래스 입력으로 시각 상태만 자극하며 새로운 공격 규칙이나 자동 타격을 만들지 않습니다.

Phase 34 - 공격 화살표의 대상 초점 표시
- 기존 Phase 33 합법 공격대상 위에만 원형 조준점과 축소/확대 반응을 더합니다.
- 모션 감소 설정에서는 정적인 표식으로 유지하고 클릭 및 전투 판정은 건드리지 않습니다.
- SVG 생성과 제거, 입력 투과를 Chromium과 WebGL에서 검증합니다.

Phase 35 - 실제 공개 체력 변화량 시각화
- 원본 전장 HP바의 이전/현재 표시 비율 차이가 생겼을 때만 카드 주변에 체력 ±N%p를 표시합니다.
- 이 수치는 화면상 HP 비율의 퍼센트포인트 변화이며 실제 공격력이나 치유량의 게임 내부 계산 결과를 뜻하지 않습니다.
- 피해는 주황, 회복은 청록. 1초 후 표시 제거, 최대 12개, 포인터 이벤트 없음, 3D 종료 시 전량 제거.
- 테스트는 공개 DOM HP바만 일시 변경하고 원상 복구해 실제 게임 상태가 바뀌지 않음을 검사합니다.

Phase 36 - 화면 크기별 Three.js 그래픽 품질과 복귀 안정성
- 작은 뷰포트에서는 3D만 약 20FPS, 큰 화면에서는 기존 약 30FPS 목표를 사용하며 게임 엔진의 시간·턴·AI는 그대로 유지합니다.
- WebGL 해상도 비율은 PC에서 최대 1.5, 좁은 화면에서는 1.25, 시스템 모션 감소 시 1.0으로 제한합니다.
- 실제 Chromium 창 크기를 FHD에서 1366x768 및 390x844로 변경했다가 복귀시키며 슬롯과 전장 클리핑, 입력 투과, 게임 스냅샷 보존을 검사합니다.
- 이 변경은 그래픽 부하 조절이지 실제 물리 기기에서의 FPS 성능 수치 측정은 아닙니다.

Phase 37 - 별도로 열 수 있는 실제 원근 3D 카드 쇼케이스
- 카드게임 화면의 3D 카드 감상 버튼으로 PerspectiveCamera를 사용한 실시간 WebGL 뷰어를 엽니다.
- 두께 있는 금속 프레임과 반사 재질, 부유 애니메이션 및 별도 조명을 표현합니다.
- 쇼케이스는 명시적으로 닫을 수 있고 원본 게임 엔진과 턴을 변경하지 않습니다.
- 현재 뷰어는 데모 카드 표현입니다. Phase 39에서 실제 필드 카드 데이터를 연결할 예정입니다.

Phase 38 - 독립 3D 디오라마 무대
- Three.js의 물리적 금속/석재 재질, 원형 받침대, 기둥, 룬 원과 실제 그림자 투영을 시네마틱 뷰어에 추가합니다.
- 카드 외관과 조명을 기존 HTML이 아닌 PerspectiveCamera 장면에서 렌더링하며 reduced-motion 설정을 유지합니다.
- 실시간 그림자와 3D 모델의 존재 여부 및 모달 종료 시 원본 게임 상태 보존을 Chromium 검증합니다.

Phase 39 - 실제 필드 카드 연동 및 장면 전환
- 공개된 전장의 카드 이름·종류·비용·표시 능력치만 읽어 3D 뷰어의 카드에 반영합니다.
- 감상 화면의 이전/다음 버튼으로 현재 전장에 보이는 카드만 둘러봅니다. 비공개 손패와 덱은 접근하지 않습니다.
- 원본 게임 로직, 선택 상태, 저장 기능에 쓰지 않으며 종료 후 상태 불변 검사를 실행합니다.
- 모바일과 FHD 모드에서 WebGL 캔버스 리사이즈와 닫기 버튼을 검증합니다.

Phase 40 - 원근 3D 카드 수동 뒤집기
- 시네마틱 뷰어에서 앞면/뒷면을 전환하는 별도 버튼을 추가했습니다.
- 뒤집기 상태는 뷰어 전용이며 공개 카드 데이터, 게임 상태, 명령에는 접근하지 않습니다.
- 카드를 바꾸면 앞면으로 복귀하고, ARIA 눌림 상태를 동기화합니다.
- Chromium에서 뒤집기·복귀·기존 엔진 상태 불변을 검사합니다.

Phase 41 - 입체 카드 뒷면 일러스트 제작
- 카드 뒷면에 512x720 고해상도 문양, 금속 테두리, 중앙 인장과 명칭을 로컬 CanvasTexture로 그립니다.
- 공개 카드 정보나 게임 규칙은 카드 뒷면 문양에 사용하지 않으며, 외부 이미지 다운로드가 필요하지 않습니다.
- 카드 뒤집기와 모드 종료 후 GPU 텍스처 해제 여부를 Chromium 테스트에 추가했습니다.

Phase 42 - 시네마틱 3D 안정성 및 반응형 렌더링
- 작은 화면에서 픽셀 비율을 최대 1.0, 3D 화면 갱신 간격을 48ms로 제한해 GPU 부담을 낮춥니다.
- 닫을 때 Three.js 렌더러와 텍스처를 해제하고 버튼으로 포커스를 복원합니다.
- 브라우저가 숨겨지면 뷰어 렌더링을 멈추고 다시 표시되면 재개합니다.
- Chromium으로 모바일 반응형, 두 차례 이상 열기/닫기, 캔버스 중복 없음 및 원본 게임 상태 보존을 검사합니다.

Phase 43 - 실제 원근 3D 뷰어 자유 시점
- 시네마틱 무대를 드래그하면 Three.js 원근 카메라의 좌우/상하 시점이 회전합니다.
- 마우스 휠 확대/축소에는 최소/최대 거리를 적용하고 시점 초기화 버튼을 제공합니다.
- 조작은 별도 감상 모달 안에서만 처리하며 원래 카드게임 입력에는 영향을 주지 않습니다.
- 실제 Chromium 드래그·휠·초기화 후 게임 상태가 변하지 않는지 검사합니다.

Phase 44 - 입체적인 신전형 마법 포탈 무대
- 기존 금속 카드 앞면을 가리지 않도록 카드 뒤에 원형 마법 포탈, 비대칭 금속 장식, 입체 등불, 파티클 조명을 설치합니다.
- 별빛 입자 180개를 1회의 Points 드로우콜로 그리며 저사양에서도 카드 UI 입력은 그대로 유지됩니다.
- 깊이 위치, 입체 재질, 원근 차이를 시각적 품질의 핵심으로 사용하며 데스크톱 Chromium에서 검증합니다.

Phase 45 - 독립 시네마틱 소환 연출
- 3D 감상 창의 소환 연출 버튼으로 금속 카드 둘레에서 두 개의 룬 링과 96개 입자가 2.3초간 퍼집니다.
- 파티클과 조명의 강도는 효과 종료 시 0으로 복구하고, 모달을 닫으면 자원을 정리합니다.
- 효과는 어디까지나 시각적 미리보기이며 기존 게임의 카드 사용, 전투, 턴 또는 체력을 바꾸지 않습니다.
- 실제 Chromium에서 발동·종료·캡처·게임 상태 불변을 검사합니다.


Phase 46 - 독립 원근 3D 전체 전장 시제품
- Phase21 HTML의 판정, AI, 손패, 턴, 저장을 수정하지 않고 기존 화면에 '입체 전장' 버튼을 추가합니다.
- 30개 공개 전장 슬롯을 실제 PerspectiveCamera 3D 공간에 여섯 줄로 배치합니다. 적 시설/후열/전열과 아군 전열/후열/시설의 순서를 보존합니다.
- 바닥, 금속 테두리, 조명, 그림자, 4개 건축 탑과 입체 카드 본체를 Three.js Mesh로 제작합니다.
- 실제 HTML의 공개 전장 슬롯에 카드가 존재할 때에만 해당 위치에 3D 카드를 표시합니다. 비공개 손패와 덱, 게임 내부 상태는 읽지 않습니다.
- 마우스 드래그 궤도 카메라, 휠 줌, 시점 초기화, 반복 열기/닫기 및 GPU 리소스 정리를 제공합니다.
- 본 Phase는 읽기 전용 원근 3D 전장 프리뷰이며 3D 카드 직접 선택·공격은 다음 Phase에서 검증할 과제입니다.
- Chromium WebGL의 1920x1080, 1366x768, 390x844 시각 캡처, 슬롯·카드 수와 게임 스냅샷 불변성 검사를 추가합니다.


Phase 47 - 3D 카드 직접 조작과 게임 입력 일치
- PerspectiveCamera 3D 전장에서는 Three.js Raycaster가 실제 카드를 맞춘 위치를 식별한다. DOM 좌표에 의존해 카드 클릭 위치를 추정하지 않는다.
- 카드 호버 시 해당 카드만 위로 떠오르고 살짝 커진다. 다른 카드 메쉬와 적 손패는 그대로 남는다. 읽기 전용 상세 툴팁을 표시한다.
- 카드를 클릭하면 기존 HTML [data-slot] 요소의 click으로 원본 slotClicked에 전달하며, 판정·피해·타겟 계산은 복제하지 않는다.
- 원본 DOM의 .legal, .attack-target, .selected-slot 클래스를 읽어 슬롯별 녹색/주황색/금색 발광 가이드를 표시한다.
- 원본 inspector의 data-actor=attack 및 data-actor=move 버튼 상태만 빌려와 3D 모달의 공격/이동/취소를 표시하고 호출한다.
- 원본 게임의 공격 대상이 선택되어 있을 때 3D 공간의 허용 대상과 공격 방향 가이드가 일치한다.
- 오비트 드래그와 클릭을 별개의 입력으로 처리해 카메라를 움직였다고 카드가 중복 선택되지 않는다.
- 30개 슬롯, 공개 카드 매핑, 기존 판정과 저장, AI, WebGL, 모바일 가독성, GPU 자원 해제를 매 Phase 검증한다.


Phase 48 - 실전 게임 이벤트 기반 WebGL 전투 파티클
- 원본 게임 함수와 전투 결과 계산은 변경하지 않는다. 현재 DOM 슬롯에 원본이 추가하는 fx-summon, fx-hit, fx-heal 클래스를 MutationObserver로 구독한다.
- 실제 발생한 신호에만 위치별 입체 충격파, 소환 링, 치유 광휘, 파편과 파티클을 생성한다. 공격 피해나 치유량을 3D 시스템에서 계산하지 않는다.
- 효과별 발생 횟수와 GPU 효과 메쉬의 수명을 확인하고, 닫기/백그라운드 진입 시 리스너 및 메쉬 자원을 해제한다.
- Chromium 검증에서 실제 합법적인 손패 카드 배치로 소환 신호를 확인한다.
- hit/heal 발광 파이프라인은 원본 visual() 함수를 사용하는 별도의 신호 테스트로 검증하며, 이를 실제 피해나 실제 치유 판정 성공으로 표시하지 않는다.


Phase 49 - 전투 시네마틱 연출, 조명·카메라·공격 궤적
- Phase48 원본 게임 신호 연동을 유지하면서 해당 효과의 입체 기둥·조명 펄스와 순간 카메라 반응을 추가한다.
- 사용자가 3D 전장의 실제 공격 가능 슬롯을 클릭하면 공격 궤적의 출발·도착 지점만 임시로 저장한다. 이 동작 자체로 피해, 적중 또는 애니메이션 확정을 만들지 않는다.
- 동일 대상의 원본 fx-hit가 2.8초 이내에 발생한 경우에만 3D 공간에 실체 있는 타격 궤적을 보인다.
- 소환·피격·치유 확정 시 원본 공개 카드 이름을 이용한 한국어 배너를 띄우며 비공개 정보는 표시하지 않는다.
- camera orbit의 영구 값은 바꾸지 않고, 초단기 카메라 떨림과 광원을 연출한다. reduced-motion 설정에서는 카메라 충격을 생략한다.
- 모든 빛 기둥과 궤적 지오메트리·재질은 수명 종료와 모달 종료 시 명시적으로 반환한다.
- Chromium 테스트에서 실제 배치 기반 소환을 검증하며 타격은 명확히 구분된 original visual helper fixture로 연출 게이트를 검증한다. fixture는 실제 전투 성공으로 간주하지 않는다.


Phase 50 - 실제 2인 대전에서의 공격·피격·피해 정합성 검증
- 3D 전장 그래픽은 원본 게임 엔진의 전투 판정을 복제하거나 G 상태를 변경하지 않는다.
- 로컬 2인 대전에서 플레이어 1/2의 실제 카드 배치, 턴 종료 및 턴 교대를 거쳐 플레이어 1의 정상 공격을 Chromium에서 검증한다.
- 3D Raycaster의 적 카드 클릭으로 원본 공격 핸들러를 실행하고, 원본 엔진의 대상 체력 감소와 행동권 소비 및 실제 fx-hit 신호가 일치하는지 확인한다.
- 시각 이펙트의 수신기록은 공개 슬롯 이름·위치·신호 유형·타임스탬프 등 최근 12건만 메모리에 기록하며, 피해 계산 결과로 오해하지 않도록 게임 UI에는 신호로 명시한다.
- 기존 Phase48/49 visual() 보조 함수 fixture 검사는 별도로 유지하며, fixture 성공을 실제 전투 판정 성공으로 바꿔 보고하지 않는다.


Phase 51 - 공개 카드의 고유 일러스트와 카메라 프리셋
- 기존 카드와 게임 판정은 그대로 사용하고, 3D 전장에 보이는 공개 카드의 이름과 종류로만 독창적인 Canvas 2D 일러스트를 생성한다.
- 건축물, 함선, 마법사, 원거리 사수, 야수, 검병의 여섯 외형을 구분하고 안정적인 카드별 색조와 전장 원근·갑주·무기·배경을 제공한다.
- 각 카드에 3D MeshStandardMaterial + CanvasTexture를 사용하는 입체 카드 몸체와 실제 피킹을 유지한다.
- 3D 전장 전체, 아군 전선, 적군 전선, 선택 카드 감상 네 카메라 프리셋을 추가한다. 프리셋은 원본 게임 상태를 변경하지 않는다.
- 선택 카드 확대 중에도 모든 나머지 카드·슬롯은 전장에 보존한다. 프리셋을 되돌리면 기본 카메라 거리 29로 복원된다.
- 데스크톱 및 모바일 Chromium WebGL 실물 캡처와 상태 불변 및 GPU 리소스 해제 테스트를 추가한다.
